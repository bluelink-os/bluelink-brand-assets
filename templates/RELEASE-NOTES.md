# BlueLink Brand Assets Release Notes Template

Reusable structure for releases after v1.0.0. Use the root RELEASE-NOTES.md for the finalized initial release.

## Release identity

State the actual version and scope. Let the GitHub release/tag provide the real publication timestamp and commit, or add verified values after publication.

## Added, changed and removed

Describe original versus derived assets, standards and policy changes. Identify exclusions and superseded materials accurately.

## Rights and integrity

Link to the applicable rights terms and manifest. Attach the intended files and checksums before publication. Never reuse a checksum after changing the bytes.

## Product separation

Keep brand identity versioning distinct from product deployments and audits. Do not reuse a smart-contract commit as the brand release commit.
