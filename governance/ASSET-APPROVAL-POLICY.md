# BlueLink Asset Approval Policy

**Version:** 1.0.0 | **Issue date:** 20 October 2026 | **Status:** Final  
**Organization:** BlueLink Blockchain Services | **Document ID:** BL-017

## Applicability

This process controls additions, replacements, new derivatives and exceptions after the initial v1.0.0 publication package. It also governs changes to the use of an existing asset, such as designating a corporate mark for a product.

## Submission

Provide the original source, intended identity, proposed filename, format, dimensions, transparency/background treatment, creator or source information and relevant rights reference. Include a preview in its intended context. A screenshot alone is not an editable master, and a file extension is not proof of its format.

## Required checks

| Check | Required result |
|---|---|
| Provenance | Source and derivation are recorded; an altered file is not labeled unchanged. |
| Rights | The intended distribution and use have a documented basis; third-party rights are addressed. |
| Visual integrity | Correct proportions, gradients, spacing, backgrounds and actual-size readability. |
| Technical hygiene | File opens correctly, dimensions match, hidden/sensitive metadata is considered, and active content is assessed where relevant. |
| Product mapping | Asset belongs to the named identity; technical lifecycle is not inferred. |
| Documentation | Manifest, guideline links, change history and source record agree. |

## Decision

The authorized representative records acceptance, rejection or limited use with a date, scope and supporting reference. Use [ASSET-APPROVAL-RECORD.md](../templates/ASSET-APPROVAL-RECORD.md) for the record. The template is deliberately uncompleted; it must never be distributed as a fictional approval.

Routine resizing that follows existing rules may be handled by the maintainer if within delegated authority. Recoloring, redraws, new wordmarks, product designation and licensing changes require the corresponding brand or rights decision.

## Release inclusion

Add only assets within the release scope. Preserve source bytes, record derivatives separately and calculate new checksums. A file that is excluded need not appear as a placeholder or a claim of completeness. Finalize the package before publication and verify the published download afterward.

## Exceptions and removals

Document the reason, affected version, allowed context and duration of an exception. For a removal, preserve the historical reference where lawful, record the reason without exposing confidential information and issue the appropriate new version.
